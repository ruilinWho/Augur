# 按钮对齐纪律

日期：2026-06-05。

作者反馈：设置·数据/信源详情页里“获取凭证 / 文档”等小按钮散落在说明区和输入行右侧，视觉上不对齐，很不美观。

## 规则

- 新增按钮前必须先确定它属于哪个操作行或操作列。
- 命令按钮（测试、保存、添加、清除、删除）使用稳定位置和固定宽度；同一页面内同类按钮要对齐。
- 信息入口（获取凭证、文档、官方入口）默认做文本链接，不伪装成按钮。
- 如果需要多个并列按钮，必须等高、等宽或落在明确栅格里；不要在正文/说明区里散放。
- UI 终检时要专门扫一遍按钮：是否换行、是否与输入框/标题/说明错位、是否和同类操作不在同一网格。

## 本次修正

- `SourceDetail` 的凭证/文档/官方入口从按钮改为同一行文本链接。
- key 输入行移除重复“获取凭证”按钮，只保留右侧操作列的保存/清除。
- 设置·全部待处理 API 的链接也改为文本入口。

## 2026-06-12 追加：综合认知标题行

- 作者截图指出「看」页综合认知区域出现明显 UI 不对齐，这是 Augur 的高优先级设计问题。
- 修正原则：模块标题行不能靠第一个计数项 `margin-left:auto` 把后续按钮“推”到右侧；这会让计数、按钮、刷新动作不在一个稳定网格里。
- `StockNews.tsx` 现在把标题行拆成：
  - 左侧标题 `h3`。
  - 右侧 `cog-head-right`，内部再分 `cog-metrics`（事件/披露/专属计数）和 `cog-head-actions`（写判断/刷新并评价）。
- `index.css` 用 grid 固定标题行列结构，按钮统一 `min-height: 32px`，移动端才换行。
- 综合认知顶部的「近况 / 社媒热度」背景卡也改为同一 grid 和 stretch 对齐；社媒的「偏多/反方/观察」用两列 grid 对齐标签与要点，不再靠 flex baseline 漂。
