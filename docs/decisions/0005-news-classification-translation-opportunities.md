# ADR 0005 — M3「知」：信源 · 分类 · 标题翻译 · 投资机会识别（防幻觉接地）

- **状态：** 已接受
- **日期：** 2026-06-02
- **决策者：** 作者 + Claude

> 作者要把「知」做深：找全球顶级前沿信源（科技/大模型/芯片/航天/机器人），把英文/韩文标题翻成中文，做好分类聚合，并让大模型判断「今天的信息带来哪些**新投资机会**、和**哪些股票**相关」。这是复杂任务，用了 workflow 并行研究/设计。

## 背景

- M3 起步版只有 12 个泛源、无分类、英文标题不可读、日报是唯一产物。作者关注的是前沿科技投资方向，需要更聚焦的源、可读的中文、清晰的分类，以及「机会→个股」的判断。
- 护栏约束：只研究不交易、不构成投资建议、**暴露不确定性**、**本地优先**（数据只发往作者配置的 LLM 厂商）、尊重限流（§1/§5/§11）。
- 现成能力：litellm 网关（角色 chat/deep_research/summarize/cheap）；`market.search`（本地目录∪东财，模糊检索→`MARKET:CODE`，带 `display_name` 中文名）；自选分区树。

## 决策

**1. 信源（41 个，workflow 发现 + 硬验证）**
- 用 workflow 派 7 个 agent 按主题（AI/芯片/航天/机器人/科技/中/韩）并行发现 RSS，再**自己用 httpx+feedparser 实测**（不信 agent 的 verified），43/45 可抓，去重定 41。清单在 `resources/sources/feeds.yaml`（作者可编辑）。
- ingest 改**并发**（ThreadPoolExecutor，41 源 ~12s）+ **近 30 天过滤**（挡归档源倒灌历史）。

**2. 分类 = 规则法（混合，零成本优先）**
- `classify_rule()`：对「标题+摘要」匹配 `resources/sources/themes.yaml` 关键词 → 9 主题（ai/chips/robotics/space/tech/markets/crypto/world/other）+ 多标签 topics；ingest store-time 同步打标。**ASCII 关键词走词边界匹配**（否则 "AI" 子串命中 "again/Thailand"）。LLM 兜底分类留待后续（避免每条调 LLM，§6）。
- 日报与「今日要闻」按主题分组（前沿在前）。

**3. 标题翻译 = cheap 角色批量（隐私决定，见替代方案）**
- `translate.py`：英文/韩文标题批量编号清单 in/out（40/批，DeepSeek JSON mode）→ 缓存 `news_items.title_zh`（每条只翻一次）。`refresh()` 抓取后触发，失败静默降级（前端回退原文）。

**4. 投资机会识别 = 两阶段，确定性接地防幻觉（核心）**
- **阶段 A（LLM，summarize/JSON）**：读当日分类新闻 → 提机会，只给「公司名 + 市场 + 可选 code_guess」、必须用 `[n]` 引用新闻、给 confidence/caveats/theme；宁缺毋滥。
- **阶段 B（确定性代码，不经 LLM）**：每个 (公司名, 市场) 用 `market.search` 解析成真实 `MARKET:CODE`——**ticker 只能来自本地目录∪东财的真实命中**（先验 LLM 的 code_guess、再强名命中、弱模糊判未解析）；再与自选分区交叉（`in_watchlist`+路径）。这是防编造 ticker 的核心闸门：模型的代码猜测仅作交叉校验、不直接采信。
- 前端「今日机会」卡：关联标的 chip 已解析可点→跳「看」研究、**已关注陶土高亮**、未解析灰显不可点；全局「非投资建议」脚注。

## 考虑过的替代方案

- **标题翻译用 DeepL / Google 翻译** —— **否决（隐私 §5）**：会把标题发往一个**未在网关体系内配置**的第三方，等于新开一条数据外发口，违背「数据只发往作者配置的厂商」；还需单独 key/额度、中文术语质量一般弱于中文原生大模型、并违背「一切走 litellm」（§6）。复用已授权的 cheap 角色零新增外发面、成本可忽略（短标题 + 缓存）。
- **分类用纯 LLM（每条调一次）** —— 否决：违反「别对每条都调 LLM」+ 限流/成本。规则先吃掉绝大多数，LLM 只留作未来兜底。
- **机会识别让 LLM 直接给 ticker** —— **否决（防幻觉）**：LLM 对代码易编造/张冠李戴，错配一个 ticker 比漏掉一个更糟。改「模型给名+市场、代码靠本地 search 解析」，把幻觉面降到最低；解析不到就只留人读名、标未解析。
- **机会生成走 SSE 逐 token 流** —— 否决：机会是结构化批数据、非正文流；用阻塞 POST + 前端 loading 更简单（与日报正文的 SSE 区分）。

## 后果

**正面**：「知」聚焦前沿、信源实测可用；英/韩标题可读中文（缓存、隐私合规）；分类聚合清晰；**机会→真实个股→自选高亮→一键跳「看」研究**，把三支柱串起来；接地防幻觉、暴露不确定性、明确非投资建议。
**代价 / 风险**：① 机会接地仍可能错配（同名/ETF/双重上市）——已设强命中阈值 + 未解析降级 + caveats，**残留风险需真机抽查调阈值**（记 memory）；② 翻译/分类/机会都依赖 cheap/summarize 厂商可用（失败均静默降级、不阻断）；③ 首次翻译存量标题较慢（160/次、按发布序、daily 任务摊平）；④ 港股/美股双重上市可能两条都出现（已知、记 memory 待迭代）；⑤ workflow 综合 agent 偶发不产出结构化结果——已改为自己读各 agent 产物兜底。
